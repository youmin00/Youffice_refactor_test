개발 개요

1. 프로젝트명

YOUFFICE
Youmin + Office의 합성어로, 사용자의 업무 요청을 여러 AI 직원이 역할별로 분담하여 처리하는 로컬 AI 오피스 프로젝트이다.


2. 프로젝트 개요

YOUFFICE는 사용자가 입력한 프로젝트 또는 업무 요청을 AI가 분석하고, 향후 프로젝트 팀장·기획 담당·기술 설계 담당·검수 담당·보고서 담당 등의 역할로 분리하여 협업하도록 설계하는 AI 오피스 시스템이다.

본 프로젝트는 단순한 질의응답 챗봇을 제작하는 데 목적이 있지 않다. AI 직원별 역할 분담, 업무 전달, 검수와 재작업, 사용자 승인, 작업 이력 관리 등 실제 조직의 업무 흐름을 소프트웨어로 구현하는 것을 목표로 한다.

현재 1차 버전에서는 로컬 AI 모델과 웹 인터페이스를 연동하여 ‘AI 프로젝트 팀장’과 대화할 수 있는 기본 시스템을 구현하였다. 이후 단계적으로 여러 AI 직원이 협업하는 멀티에이전트 구조로 확장할 예정이다.


3. 개발 배경

최근 생성형 AI를 단순한 대화 도구가 아니라 특정 역할을 수행하는 ‘AI 직원’ 또는 ‘AI 에이전트’로 활용하는 사례가 증가하고 있다. 특히 하나의 요청을 여러 AI가 기획, 분석, 실행, 검수 등의 단계로 나누어 처리하는 AI 오피스 형태가 주목받고 있다.

이에 따라 최신 AI 활용 흐름을 직접 이해하고, 단순 API 호출을 넘어 AI 모델 실행, 웹 인터페이스, 업무 흐름 설계, 상태 관리 및 자동 실행 구조를 포함한 개인 포트폴리오 프로젝트를 개발하고자 하였다.


4. 개발 목적

가. 로컬 AI 모델을 직접 구동하고 Python 프로그램과 연동한다.

나. 사용자가 쉽게 업무를 요청할 수 있는 웹 기반 인터페이스를 구현한다.

다. AI 직원별 역할과 책임을 정의하고 업무가 단계적으로 전달되는 구조를 설계한다.

라. 검수 실패 시 이전 단계로 돌아가는 재작업 흐름을 구현한다.

마. AI의 자동 처리와 사용자의 승인 절차를 결합한다.

바. 외부 유료 API에만 의존하지 않고 실행 가능한 AI 시스템을 구축한다.

사. 로봇·비전·제어 프로젝트 경험과 AI 에이전트 기술을 결합한 포트폴리오를 완성한다.


5. 프로젝트 주제 선정 이유

일반적인 AI 챗봇은 사용자의 질문에 한 번 답변하는 구조가 대부분이므로, 프로젝트의 기술적 차별성을 보여주기 어렵다. 반면 AI 오피스는 하나의 업무를 여러 역할로 분리하고, 각 결과를 다음 직원에게 전달하며, 검수와 재작업까지 수행한다.

이 구조는 다음과 같은 역량을 함께 보여줄 수 있다는 점에서 포트폴리오 주제로 선정하였다.

- 생성형 AI 및 로컬 LLM 활용 능력
- Python 기반 시스템 통합 능력
- 사용자 인터페이스 설계 능력
- 업무 흐름 및 알고리즘 설계 능력
- 멀티에이전트 구조 이해
- 오류 처리와 검수 로직 설계
- 실행 환경 자동화 능력


6. 개발 방향 선정 방안

본 프로젝트는 다음 기준에 따라 개발 방향과 기술을 선정하였다.

첫째, 초기 비용이 낮아야 한다.
AI 직원이 여러 번 모델을 호출하는 구조에서는 유료 API 사용량이 빠르게 증가할 수 있다. 포트폴리오 제작 단계에서는 반복적인 실험이 필요하므로, 로컬 AI 모델을 기본 실행 환경으로 선정하였다.

둘째, 개인 노트북에서 실행할 수 있어야 한다.
별도의 서버나 고가의 클라우드 인프라 없이 Windows 노트북에서 직접 실행할 수 있는 구조를 우선하였다.

셋째, 기능 확장이 쉬워야 한다.
초기에는 AI 직원 한 명으로 시작하지만, 이후 기획자·설계자·검수자 등 여러 역할을 추가할 수 있도록 Python 기반 구조를 선택하였다.

넷째, 사용자가 쉽게 접근할 수 있어야 한다.
터미널에서만 동작하는 프로그램은 시연과 사용성이 떨어지므로, 브라우저에서 사용할 수 있는 웹 인터페이스를 적용하였다. 또한 실행 파일을 더블클릭하면 Ollama와 웹 서버가 자동으로 실행되도록 구성하였다.

다섯째, 구현 과정이 포트폴리오에서 설명 가능해야 한다.
단순히 완성된 서비스를 사용하는 것이 아니라, 모델 실행 환경, 웹 UI, 프로그램 연동, 상태 관리, 실행 자동화 과정을 직접 구성할 수 있는 기술을 선정하였다.


7. 주요 기술 및 선정 이유

7.1 Python 3.12

AI 모델 호출, 업무 흐름 제어, 데이터 처리 및 웹 애플리케이션 개발에 사용한다. 다양한 AI 관련 라이브러리를 활용할 수 있고, 기존 로봇 및 비전 프로젝트 경험과 연결하기 용이하여 선정하였다.


7.2 Ollama

Ollama는 AI 모델 자체가 아니라, 로컬 AI 모델을 개인 컴퓨터에서 실행하고 Python 프로그램이 해당 모델을 호출할 수 있도록 지원하는 실행 환경이다.

선정 이유는 다음과 같다.

- 모델 사용에 따른 별도 API 호출 비용이 없음
- Windows에서 설치와 실행이 비교적 간단함
- 로컬 API를 통해 Python과 연동 가능함
- 필요에 따라 다른 로컬 모델로 교체 가능함
- 인터넷 연결이 제한된 환경에서도 활용 가능함


7.3 Qwen3 4B

현재 YOUFFICE에서 실제 응답을 생성하는 로컬 AI 모델이다. 보유 노트북의 GPU 메모리와 실행 속도를 고려하여 4B급 모델을 선정하였다.

Qwen3 4B는 비용 없이 반복 실험하기에 적합하지만, 대형 상용 모델보다 복잡한 추론과 긴 문서 처리 성능이 낮을 수 있다. 따라서 향후 로컬 모델과 고성능 클라우드 모델을 선택적으로 사용하는 하이브리드 구조도 검토할 예정이다.


7.4 Streamlit

Python 코드만으로 브라우저 기반 화면을 제작할 수 있는 웹 애플리케이션 프레임워크이다.

선정 이유는 다음과 같다.

- 별도의 복잡한 프론트엔드 개발 없이 화면 구현 가능
- 채팅 입력창, 사이드바, 버튼, 상태 표시 등을 빠르게 구현 가능
- 포트폴리오 시연용 화면 제작에 적합
- Python 기반 AI 로직과 직접 연결하기 쉬움


7.5 Python 가상환경

YOUFFICE 전용 가상환경을 구성하여 다른 프로젝트와 라이브러리 충돌이 발생하지 않도록 하였다. 프로젝트에 필요한 Streamlit과 Ollama Python 라이브러리를 독립적으로 설치하고 관리한다.


7.6 실행 자동화 스크립트

사용자가 VS Code를 열고 가상환경을 활성화한 뒤 명령어를 입력해야 하는 불편을 줄이기 위해 실행 스크립트를 제작하였다.

현재 실행 파일을 더블클릭하면 다음 과정이 자동으로 수행된다.

- Ollama 실행 상태 확인
- Ollama가 꺼져 있을 경우 자동 실행
- YOUFFICE의 Streamlit 서버 실행
- 서버 준비 상태 확인
- 웹브라우저에서 YOUFFICE 화면 열기


7.7 ChatGPT Plus 활용

ChatGPT Plus는 현재 YOUFFICE 내부의 AI 직원으로 직접 연결된 것이 아니라, 프로젝트 설계, 코드 작성, 오류 분석 및 기능 개선을 지원하는 개발 도구로 활용하고 있다.

ChatGPT Plus 이용권과 OpenAI API 사용료는 별도이므로, Plus 구독만으로 YOUFFICE가 GPT를 자동 호출할 수는 없다. 향후 필요할 경우 별도의 API를 연결하여 로컬 Qwen 모델과 GPT 계열 모델을 선택적으로 사용하는 기능을 추가할 수 있다.

9. 현재 구현 기능

2026년 8월 기준 현재 구현된 기능은 다음과 같다.

- Windows 환경에서 Ollama 설치
- Qwen3 4B 로컬 모델 다운로드 및 실행
- YOUFFICE 전용 Python 3.12 가상환경 구성
- Streamlit 및 Ollama Python 라이브러리 설치
- 브라우저 기반 YOUFFICE 채팅 화면 구현
- AI 프로젝트 팀장 역할 프롬프트 적용
- 한국어 업무 요청 및 응답 기능 구현
- 대화 내용의 세션 단위 유지
- 대화 초기화 버튼 구현
- 모델의 사고 과정 표시 비활성화
- 실행 파일 더블클릭을 통한 자동 실행
- 기존 서버 실행 여부 확인 후 브라우저 재접속


10. 현재 개발 단계의 한계

현재 버전은 AI 프로젝트 팀장 한 명과 대화하는 기본 구조이다. 따라서 아직 여러 AI 직원이 실제로 역할을 나누어 협업하는 멀티에이전트 시스템은 구현되지 않았다.

또한 현재 대화 기록은 브라우저 세션에 저장되므로, 프로그램을 완전히 종료한 후에도 영구적으로 유지되는 데이터베이스 기능은 아직 적용되지 않았다.

Qwen3 4B는 로컬 실행에 적합한 소형 모델이므로, 복잡한 기술 설계나 긴 문서 검수에서는 결과 품질이 제한될 수 있다.


11. 향후 개발 계획

11.1 AI 직원 역할 확장

- AI 프로젝트 팀장
- 기획 담당
- 기술 설계 담당
- 안전·품질 검수 담당
- 최종 보고서 담당


11.2 업무 분배 기능

사용자의 요청을 AI 팀장이 분석한 뒤, 필요한 업무와 담당 직원을 자동으로 결정하도록 개발한다.


11.3 직원 간 결과 전달

기획 담당의 결과를 기술 설계 담당에게 전달하고, 기술 설계 결과를 검수 담당에게 전달하는 순차 업무 흐름을 구현한다.


11.4 검수 및 재작업

검수 담당이 문제나 누락 사항을 발견하면 기술 설계 단계로 결과를 되돌리고, 수정 후 재검수를 수행하는 반복 구조를 구현한다.


11.5 사용자 승인 기능

AI 팀장이 작성한 업무 계획을 사용자가 승인하거나 수정한 뒤 다음 단계로 넘어가도록 구현한다. AI의 완전 자동 실행보다 사람의 판단이 포함된 Human-in-the-loop 구조를 적용한다.


11.6 작업 상태 시각화

각 직원의 상태를 다음과 같이 표시한다.

- 대기
- 업무 분석 중
- 작업 중
- 검수 중
- 수정 요청
- 완료


11.7 업무 기록 저장

SQLite 데이터베이스를 연동하여 프로젝트명, 사용자 요청, 직원별 결과, 검수 내용, 최종 보고서를 저장한다. 프로그램을 다시 실행해도 과거 프로젝트를 조회할 수 있도록 개발한다.


11.8 결과물 생성

최종 결과를 프로젝트 제안서, 검수 보고서 또는 개발 계획서 형태로 정리하고 텍스트 또는 문서 파일로 내려받을 수 있도록 구현한다.


11.9 모델 선택 기능

기본적으로 무료 로컬 모델을 사용하되, 향후 필요에 따라 다음과 같은 선택 기능을 검토한다.

- 로컬 모드: Ollama 기반 Qwen 모델
- 고성능 모드: 별도 API를 이용한 클라우드 모델

이를 통해 비용과 성능을 사용자가 선택할 수 있는 하이브리드 AI 오피스로 확장할 수 있다.


12. 차별화 방안

일반적인 AI 오피스 예제는 마케팅 문구, 여행 일정 또는 단순 문서 작성 업무에 집중하는 경우가 많다.

YOUFFICE는 개발자의 메카트로닉스 및 로봇 프로젝트 경험을 반영하여 기술 프로젝트 기획과 검수에 특화된 AI 오피스로 발전시키는 것을 차별화 방향으로 설정한다.

예를 들어 사용자가 비전 기반 로봇팔 자동 분류 시스템을 요청하면 다음 내용을 역할별로 처리할 수 있다.

- 프로젝트 목표 및 요구사항 정리
- 카메라·로봇팔·제어부 시스템 구성
- 소프트웨어와 하드웨어 개발 단계 설계
- 좌표계, 통신, 충돌, 안전 조건 검토
- 누락 사항 수정
- 최종 프로젝트 제안서 작성


13. 기대 효과

가. 최신 AI 에이전트 기술에 대한 이해를 실제 구현 경험으로 증명할 수 있다.

나. 단순 챗봇이 아닌 업무 흐름 기반 AI 시스템 설계 역량을 보여줄 수 있다.

다. 로컬 LLM을 활용하여 비용과 개인정보 측면의 장점을 설명할 수 있다.

라. Python, 웹 UI, 로컬 API, 실행 자동화 및 향후 데이터베이스를 하나의 시스템으로 통합한 경험을 확보할 수 있다.

마. 기존 로봇·비전·제어 경험과 AI 기술을 연결하여 지원 직무와 연관된 차별화된 포트폴리오를 구성할 수 있다.


14. 포트폴리오 핵심 설명

YOUFFICE는 사용자의 기술 프로젝트 요청을 AI 직원들이 기획, 설계, 검수 및 보고 단계로 분담하여 처리하도록 개발하는 로컬 AI 오피스이다. Python과 Streamlit으로 웹 인터페이스를 구현하고, Ollama를 통해 Qwen3 4B 로컬 모델을 연동하였다. 현재 AI 프로젝트 팀장과 대화할 수 있는 1차 버전과 실행 자동화를 완성했으며, 향후 멀티에이전트 협업, 검수 재작업, 사용자 승인 및 작업 이력 저장 기능을 추가할 예정이다.


15. 한 줄 소개

개발 배경

프로젝트명: YOUFFICE

슬로건:
혼자 시작해도, 다음 행동은 선명하도록.

서비스 설명:
막연한 아이디어를 실제로 시작할 수 있는 준비서로 바꾸고, 실행 과정의 결정과 문제를 연결하는 AI 프로젝트 오피스


1. 개발 배경

대학생에게 졸업 작품과 개인 프로젝트는 전공 역량을 증명하고 포트폴리오를 만드는 중요한 기회다. 그러나 혼자 프로젝트를 시작하면 아이디어 회의, 자료 조사, 요구사항 정리, 기술 선택, 일정 관리, 오류 해결, 시험과 문서화를 모두 한 사람이 맡아야 한다.

이 과정에서 가장 큰 어려움은 단순히 답을 모르는 것이 아니다. 지금 무엇을 결정해야 하는지, 어떤 정보는 아직 몰라도 되는지, 여러 선택 중 무엇을 어떤 근거로 골라야 하는지 판단하기 어렵다. 해야 할 일이 계속 늘어나면 실제 제작이나 개발을 시작하기 전에 지치거나 프로젝트를 포기할 수 있다.

개발자 역시 졸업 작품과 대학 프로젝트를 수행하며 같은 문제를 경험했다. 프로젝트를 함께 검토할 팀원이 부족했고, 좋은 아이디어가 있어도 무엇부터 조사하고 어떤 순서로 구현해야 하는지 정리하는 데 많은 시간이 필요했다.

2. 기존 생성형 AI 활용의 한계

GPT나 Gemini와 같은 생성형 AI는 코드 예시, 오류 설명, 아이디어와 문서 작성에서 높은 성능을 낸다. 실제 개발 중 구체적인 기술 질문을 해결하는 데에는 범용 AI가 더 적합할 수 있다.

그러나 프로젝트를 여러 대화에 걸쳐 진행하면 답변과 자료가 흩어지고, 과거에 결정한 조건과 현재 질문이 연결되지 않기 쉽다. AI가 제안한 내용, 사용자가 확정한 내용, 실제로 시험한 결과가 한 문서에서 섞이는 문제도 생긴다.

또한 일반적인 대화형 AI가 부족한 정보를 확인하려고 질문을 계속하면 사용자가 모든 세부사항을 먼저 정해야 하는 상황이 발생한다. 초보 학생은 답을 얻기 위해 AI를 사용했지만 오히려 질문에 답하는 부담을 느낄 수 있다.

YOUFFICE는 범용 AI보다 모든 기술 답변을 더 잘하는 것을 목표로 하지 않는다. 범용 AI와 외부 도구의 결과를 프로젝트의 요구사항, 결정, 출처, 오류와 다음 행동으로 연결하는 것을 목표로 한다.

3. 방향 전환의 필요성

초기 YOUFFICE는 여러 AI 직원이 아이디어 기획부터 제작과 보고서까지 프로젝트 전체를 함께 수행하는 모습을 지향했다. 그러나 실제 프로젝트에는 CAD 도면, 부품 구매, 조립, 코드 실행, 장비 측정과 안전 시험처럼 AI 대화만으로 완료할 수 없는 작업이 포함된다.

이 영역까지 직접 수행한다고 약속하면 시스템이 지나치게 무거워지고, 실제로 하지 않은 일을 완료한 것처럼 표현할 위험이 커진다. 결과적으로 기능은 많지만 사용자가 무엇을 얻는지 불명확한 서비스가 될 수 있다.

따라서 YOUFFICE의 중심을 프로젝트 대행에서 프로젝트 준비와 연결로 전환한다. 프로젝트를 실제로 수행하는 주체는 사용자이며, YOUFFICE는 사용자가 실제 행동을 시작하고 중간에 방향을 잃지 않도록 돕는 프로젝트 오피스가 된다.

4. YOUFFICE가 제공하는 도움

프로젝트 시작 전
- 한 문장 아이디어를 목표와 요구사항으로 바꾼다.
- 초기 핵심 질문은 최대 3개 안에서 하고 초안을 먼저 보여 준다.
- 사용자가 원하는 항목은 횟수 제한 없이 하나씩 더 구체화한다.
- 사용자가 유키에게 묻는 질문은 먼저 답하고 초기 질문 횟수에 포함하지 않는다.
- 모르는 항목은 기본 가정과 미확인 사항으로 구분한다.
- 선택지, 조사 자료, 예산, 일정, 위험과 테스트 기준을 정리한다.
- CAD·개발·제작 도구로 넘길 준비 체크리스트를 만든다.

프로젝트 실행 중
- 실제로 선택한 부품, 구조와 개발 방법을 기록한다.
- 오류와 시험 결과를 이전 결정에 연결한다.
- 예상과 실제 결과의 차이를 검토하고 다음 수정안을 정리한다.
- 필요하면 범용 AI나 전문 도구에 물어볼 정확한 질문을 만든다.

프로젝트 정리 단계
- 실제 수행 내용과 AI 제안을 구분한다.
- 결정 이유, 문제 해결 과정과 시험 결과를 보고서로 정리한다.
- 미완료 항목과 다음 행동을 남긴다.

5. YOUFFICE가 직접 하지 않는 일

YOUFFICE는 다음 작업을 수행하거나 완료를 보증하지 않는다.

- 정밀 CAD 도면 작성
- 실제 부품 구매·가공·조립
- 코드 실행과 배포
- 실제 장비의 성능·안전·사용성 시험
- 전문 자격이 필요한 최종 판단

대신 사용자가 제공한 도면, 코드, 사진과 시험 결과를 바탕으로 빠진 조건, 위험, 수정 항목과 다음 테스트를 정리한다.

6. AI 오피스 구조의 의미

여러 AI 직원은 단순히 같은 챗봇에 다른 이름을 붙인 것이 아니다. 프로젝트 준비에 필요한 관점을 역할별로 분리한다.

- 유키는 질문을 제한하고 현재 정보를 제작 준비 계획으로 바꾼다.
- 희정은 요구사항과 결정·변경 이력을 관리한다.
- 리오는 조사, 선택 기준, 예산과 일정을 정리한다.
- 미츠리는 기술 요구사항과 외부 도구 전달 조건을 만든다.
- 레비는 근거, 누락, 위험과 실제 확인 항목을 검토한다.
- 마코는 결과를 프로젝트 준비서와 진행 보고서로 통합한다.

직원들의 결과는 서로 전달되고 검토되지만 실제 작업을 수행했다는 증거로 취급하지 않는다. 오피스의 시각화는 프로젝트의 제작 완료율이 아니라 준비 자료 작성과 검토 진행 상태를 보여준다.

7. 기대하는 사용자 경험

사용자가 “집중을 도와주는 책상 장치를 만들고 싶다”고 입력하면 유키는 모든 세부사항을 요구하지 않는다. 목적과 큰 제약을 확인하는 핵심 질문만 하고, 나머지는 기본 가정이나 미확인으로 남긴다.

직원들은 요구사항, 센서 선택 기준, 예상 위험, 조사할 자료, 외부 CAD 작업에 필요한 치수 목록과 시험 계획을 정리한다. 사용자는 프로젝트 준비서를 들고 실제 부품 조사, 도면 작성, 코딩과 시제품 제작을 시작한다.

제작 중 “햇빛에서 센서가 오작동했다”는 결과를 입력하면 YOUFFICE는 이를 오류 기록에 연결하고 원인 후보, 변경할 조건과 다음 시험을 정리한다. 최종 보고서에는 처음 선택 이유와 실제 문제 해결 과정이 함께 남는다.

8. 제품의 차별점

GPT가 좋은 답을 제공한다면, YOUFFICE는 그 답이 프로젝트에서 사라지지 않도록 관리한다.

핵심 차별점은 다음과 같다.

- 질문을 무한히 이어가지 않는 명확한 종료 조건
- 프로젝트별 장기 맥락과 기록
- 확정·가정·미확인·실행 결과의 구분
- 조사 자료와 선택 이유의 연결
- 여러 역할을 통한 독립 검토
- 외부 도구로 넘길 수 있는 프로젝트 준비서
- 실제 제작·개발 중 발생한 결정과 오류의 추적

9. 핵심 사용자와 성공 기준

핵심 사용자는 처음으로 규모 있는 졸업 작품이나 개인 프로젝트를 혼자 진행하는 학생이다.

YOUFFICE를 사용한 뒤 사용자가 다음 행동을 설명할 수 있어야 한다.

- 무엇을 만들 것인지
- 무엇이 확정됐고 무엇이 아직 가정인지
- 어떤 선택지를 왜 검토하는지
- 실제 작업 전에 무엇을 확인할지
- CAD·개발·제작 도구에서 지금 무엇을 할지

이 결과가 10~20분 안에 프로젝트 준비서로 만들어지고, 실행 중 기록과 보고서로 이어질 때 YOUFFICE의 방향성이 실제 사용자 가치로 연결된 것으로 판단한다.

10. 개발 배경 요약

YOUFFICE는 프로젝트를 대신 완성하는 AI가 아니다. 혼자 프로젝트를 시작하는 학생의 막연함을 줄이고, 아이디어를 실제 행동 가능한 준비서로 바꾸며, 외부 도구와 실제 작업에서 나온 결과를 프로젝트의 다음 결정으로 연결하는 AI 프로젝트 오피스다.

혼자 시작해도, 다음 행동은 선명하도록.
